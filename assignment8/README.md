# 과제 08 — 최소 비용 신장 트리(MST) 알고리즘 비교

## 1. 과제 개요

정점이 50개인 **가중치 무방향 단순 연결 그래프**를 희소 그래프(간선 100개)와 밀집 그래프(간선 600개)로 각각 생성하고, **인접 리스트 + Kruskal** 및 **인접 행렬 + Prim** 조합으로 최소 비용 신장 트리(MST)를 구한다. 각 경우에 대해 MST 간선, 간선 개수, 총비용, 자료구조 메모리 용량(Byte), 실행시간(ms)을 확인하고 결과를 비교한다.

| Case | 그래프 | 정점(V) | 간선(E) | 그래프 표현 | MST 알고리즘 |
|:---:|---|---:|---:|---|---|
| 1 | 희소 | 50 | 100 | 인접 리스트 | Kruskal |
| 2 | 밀집 | 50 | 600 | 인접 리스트 | Kruskal |
| 3 | 희소 | 50 | 100 | 인접 행렬 | Prim |
| 4 | 밀집 | 50 | 600 | 인접 행렬 | Prim |

**공정한 비교 조건:** Case 1과 3은 완전히 동일한 정점·간선·가중치를 사용하고, Case 2와 4 역시 동일한 그래프를 사용한다. 희소 그래프와 밀집 그래프 자체는 별도로 생성되므로, 두 그래프의 MST 총비용이 서로 다르는 것은 정상이다.

## 2. 제출 파일 구성

- `main.c`: 그래프 생성, 인접 리스트/행렬 생성, Kruskal/Prim, MST 및 그래프 검증, 메모리·시간 측정, 결과 출력까지 포함한 C11 소스 코드
- `README.md`: 실행 안내, 실제 실행 결과 및 분석

## 3. 실행 방법

**macOS / Linux (터미널, 권장 옵션):**

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c -o main
./main
```

**Windows (PowerShell + GCC/MinGW-w64):**

```powershell
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c -o main.exe
.\main.exe
```

- 실제 측정에 사용한 MacBook 명령은 `gcc main.c -o main`이며, 위의 최적화 옵션(`-O2`)을 사용하는 경우 실행시간이 달라질 수 있다.
- 인자 없이 실행하면 현재 시각을 이용해 난수 시드를 정한다.
- 특정 시드를 전달하면 **같은 실행 환경의 C 난수 구현에서** 동일한 그래프를 다시 생성할 수 있다. 예: `./main 1792034740` 또는 Windows에서 `.\main.exe 1792034740`.
- 시드가 같더라도 운영체제/C 라이브러리에 따라 `rand()`가 생성하는 수열은 달라질 수 있다. **실행시간은 매번 달라지는 것이 정상이다.**
- 입력 없이 자동 실행되며, 결과에는 **각 케이스의 MST 간선 49개 전부**와 마지막 4개 케이스 비교표를 출력한다.

## 4. 그래프 생성 및 MST 구현

### 4-1. 랜덤 그래프 생성 및 유효성 검사

1. 정점 번호는 `0~49`이고, 간선 가중치는 **1~1000의 양의 정수**다.
2. 먼저 각 정점 `i(1~49)`를 이전 정점 `0~i-1` 중 하나와 연결하여 **49개의 간선으로 연결성을 보장하는 신장 트리**를 생성한다.
3. 이후 간선을 무작위로 추가하여 희소 그래프는 100개, 밀집 그래프는 600개가 되도록 만든다.
4. `exists[u][v]`와 `u != v` 검사를 통해 중복 간선과 자기 루프를 방지한다.
5. 생성이 끝난 다음 `validate_graph()`가 **정점 범위 / 양의 가중치 / 자기 루프 없음 / 중복 간선 없음 / Union-Find 연결성**을 다시 검증한다. 검증 실패 시 오류 메시지를 출력하고 종료한다.

### 4-2. Kruskal (인접 리스트)

- 무방향 간선 하나는 인접 리스트에서 `u→v`, `v→u` 두 노드로 보관한다.
- 알고리즘 내부에서 `u < v`인 항목만 수집하여 각 무방향 간선을 정확히 **한 번씩** 간선 배열에 넣는다.
- `qsort()`로 가중치 오름차순 정렬(동점이면 정점 번호로 정렬)한 뒤, `Union-Find`의 경로 압축과 rank 기반 합치기를 사용하여 사이클이 생기지 않는 간선만 선택한다.
- MST가 49개 간선을 갖는 즉시 종료하며, 전체 간선 정렬과 보조 구조 생성도 실행시간 측정에 포함한다.
- 시간 복잡도: **O(E log E)**(간선 정렬이 지배적), 자료구조 저장량은 간선 수가 증가할수록 증가한다.

### 4-3. Prim (인접 행렬)

- `weights[50][50]`에 가중치를 대칭으로 저장하고, `0`은 간선이 없음을 뜻한다(실제 가중치는 항상 양수).
- 정점 0에서 시작하여 `key[50]`(MST까지 최소 연결 비용), `parent[50]`(선택될 간선의 이전 정점), `visited[50]`(방문 여부)를 관리한다.
- 매 단계 방문하지 않은 정점 중 `key`가 최소인 정점을 선형 탐색으로 선택하고 인접 행렬을 순회해 비용을 갱신한다.
- 정점 50개가 모두 포함되면 종료한다.
- 시간 복잡도: **O(V²)**(행렬에서 매번 정점을 선형 탐색), 저장량 역시 간선 수가 아니라 **V²**에 의해 크게 결정된다.

### 4-4. MST 결과 검증

각 MST에 대해 다음 조건을 독립적으로 검사한다.

- 선택한 간선이 **원본 그래프에 실제로 존재**하며, 가중치도 동일한가?
- 선택된 간선들이 **사이클을 만들지 않는가?**
- **정점 50개가 모두 연결**되는가? / **간선 49개**가 맞는가?
- 선택한 간선 가중치의 합이 표시된 **MST Cost**와 같은가?
- 동일한 희소/밀집 그래프에서 **Kruskal과 Prim의 MST Cost가 일치**하는가?

가중치가 같은 간선이 여러 개 있으면 두 알고리즘의 간선 구성이 달라질 수 있으나, 최소 신장 트리의 **총비용은 반드시 같아야 한다.** 조건을 위반하면 프로그램은 오류 메시지와 함께 종료한다.

## 5. 메모리 및 실행시간 측정 방법

### 5-1. 메모리: `sizeof`로 자료구조 용량 계산

프로그램에서는 **각 케이스가 사용하는 그래프 표현 + MST 계산에 필요한 주요 보조 자료구조 + MST 결과 저장 공간**의 합을 Byte 단위로 계산했다.

| 측정 항목 | Case 1(희소 Kruskal) | Case 2(밀집 Kruskal) | Case 3·4(Prim) |
|---|---:|---:|---:|
| 그래프 구조체(`ListGraph`/`MatrixGraph`) | 408 B | 408 B | 10,004 B |
| 인접 리스트 노드(`2E × sizeof(AdjNode)`) | 3,200 B | 19,200 B | 해당 없음 |
| 간선 정렬 배열(`E × sizeof(Edge)`) | 1,200 B | 7,200 B | 해당 없음 |
| Union-Find(`sizeof(DisjointSet)`) | 400 B | 400 B | 해당 없음 |
| Prim의 `key[50]` / `parent[50]` / `visited[50]` | 해당 없음 | 해당 없음 | 450 B |
| MST 결과 저장(`sizeof(MSTResult)`) | 600 B | 600 B | 600 B |
| **합계** | **5,808 B** | **27,808 B** | **11,054 B** |

※ 위 바이트 수는 **사용자가 실행한 macOS 환경에서 프로그램이 계산한 `sizeof` 결과**로, 포인터 크기·구조체 정렬 등에 따라 환경별 차이가 날 수 있다. `malloc` 내부 관리 영역, C 라이브러리 `qsort` 구현 내부 공간, 난수 생성/원본 간선 생성용 임시 버퍼, 출력 관련 버퍼는 포함하지 않는다. 이는 전체 프로세스의 실제 점유 메모리(RSS)가 아니라 **과제에서 지정한 핵심 자료구조의 용량 계산값**이다.

### 5-2. 실행시간: MST 계산만 측정

- 랜덤 그래프 및 인접 리스트/행렬 **생성은 측정 전에 완료**한다.
- MST 알고리즘 실행 직전부터 직후까지의 경과시간을 기록한다. **간선 출력·결과표 출력·사후 정합성 검증은 시간 측정에서 제외**한다.
- 너무 작은 실행시간으로 인한 측정 오차를 줄이기 위해 **같은 그래프에서 1,000번 MST 계산을 반복하고 총 소요시간을 1,000으로 나눈 평균값**을 사용한다. 네 경우 모두 반복 수와 단위를 동일하게 적용한다.
- **macOS/Linux:** `clock_gettime(CLOCK_MONOTONIC)` / **Windows:** `QueryPerformanceCounter()`를 사용하며, 모두 **밀리초(ms), 소수점 6자리**로 출력한다.
- Kruskal 측정에는 간선 추출·정렬·Union-Find·MST 선택이 포함된다. Prim 측정에는 `key`/`parent`/`visited` 초기화와 최소 정점 선택·갱신이 포함된다.

## 7. 측정값을 바탕으로 한 비교·분석

### 7-1. 희소 그래프와 밀집 그래프의 성능 차이

희소(100개)에서 밀집(600개)으로 간선 수가 **6배**가 되자, 인접 리스트 + Kruskal의 메모리는 **5,808 → 27,808 B**로 증가했다. 이는 무방향 간선을 양쪽 방향으로 저장한 **인접 리스트 노드가 200개에서 1,200개로**, 정렬에 필요한 간선 배열이 100개에서 600개로 증가하기 때문이다. 실행시간도 **0.008668 → 0.051741 ms**, 약 **5.97배**로 늘었다. 간선을 순회하고 정렬하는 작업량이 간선 수의 영향을 크게 받는다는 점을 확인할 수 있다.

반면 인접 행렬 + Prim의 메모리는 간선 수와 무관하게 **11,054 B로 일정**했다. 인접 행렬은 간선이 없어도 항상 50×50개의 칸을 확보하기 때문이다. 실행시간은 **0.011268 → 0.011603 ms**, 약 **1.03배**가 되었다. 이 구현은 모든 정점을 대상으로 탐색하는 **O(V²)** 방식이라 정점 수가 고정된 상황에서는 간선 수 증가에 따른 비용 변화가 Kruskal에 비해 작게 관측되었다. 다만 작은 시간 차이에는 캐시, 분기, 운영체제 스케줄링 및 측정 오차가 영향을 줄 수 있고, 컴파일 최적화 옵션에 따라서도 달라진다.

### 7-2. 인접 리스트와 인접 행렬의 메모리 차이

희소 그래프에서는 **인접 리스트 + Kruskal 5,808 B < 인접 행렬 + Prim 11,054 B**였다. 간선이 적을 때 리스트는 실제로 존재하는 간선에 비례해 노드를 저장하지만, 행렬은 간선이 없는 위치까지 모두 보관하므로 상대적으로 공간 낭비가 발생한다.

밀집 그래프에서는 반대로 **인접 리스트 + Kruskal 27,808 B > 인접 행렬 + Prim 11,054 B**로 나타났다. 간선이 많아지면 리스트에 필요한 연결 노드 및 정렬 배열 공간이 계속 증가하지만, 행렬의 크기는 고정되기 때문이다. 단, 본 측정값에는 **그래프 표현뿐 아니라 Kruskal의 정렬 배열과 Union-Find, Prim의 보조 배열**도 포함되어 있다. 따라서 위 수치 전체를 순수한 **인접 리스트 vs 인접 행렬 자체의 메모리 차이**로 해석해서는 안 된다.

### 7-3. Kruskal과 Prim의 실행 특성 차이

Kruskal은 **모든 간선을 정렬**한 후 사이클 여부를 판단하면서 MST를 구성하므로, 간선이 적은 희소 그래프에서는 다룰 데이터가 적지만 간선이 많은 밀집 그래프에서는 정렬 비용이 증가한다. Prim은 인접 행렬에서 최소 연결 비용을 가진 정점을 매번 **50개 정점 중 선형 탐색**하므로, 같은 정점 수라면 간선 수 증가의 영향을 상대적으로 적게 받는다.

이번 실험의 **희소 그래프**에서는 Kruskal **0.008668 ms**, Prim **0.011268 ms**로 Kruskal이 약 **1.30배 빠르게** 측정되었다. 다만 절대 시간 차이는 **0.002600 ms(2.6 μs)**이므로 한 번의 실행 결과만으로 모든 환경에서 Kruskal이 더 빠르다고 일반화할 수 없다. **밀집 그래프**에서는 Kruskal **0.051741 ms**, Prim **0.011603 ms**로 Prim이 이 측정에서 약 **4.46배 빠르게** 나타났다. 이는 간선 정렬을 수행하는 Kruskal과 정점 수에 주로 비례하는 행렬 기반 Prim의 구현 방식 차이를 반영한다.

### 7-4. 그래프 밀도에 따른 종합 해석

이번 실험에서 희소 그래프에서는 **인접 리스트 + Kruskal 조합의 메모리 사용량과 실행시간이 모두 더 작았고**, 밀집 그래프에서는 **인접 행렬 + Prim 조합이 메모리와 실행시간 모두 유리**했다. 특히 그래프가 밀집될수록 인접 리스트 노드와 정렬용 간선 배열이 함께 증가한 반면, 인접 행렬의 크기와 행렬 기반 Prim의 반복 구조는 정점 수 50개에 따라 제한된다는 사실을 측정 수치로 확인했다.

**비교의 한계:** 과제에서 지정한 네 경우는 표현 방식과 MST 알고리즘이 **동시에 바뀌는 조합 비교**다. 따라서 이 결과만으로 메모리/시간 차이를 **표현 방식만의 효과** 또는 **알고리즘만의 효과**로 완전히 분리해 결론 내릴 수 없다. 또한 한 번 생성한 각 그래프의 결과이므로, 여러 난수 시드와 반복 실험을 추가하면 결과의 일반성을 더 확인할 수 있다.

## 8. 결론

정점 50개, 간선 100개와 600개인 연결 그래프에서 MST를 각각 구한 결과, 네 경우 모두 **간선 수 49개**를 만족했고 동일한 그래프를 사용한 Kruskal과 Prim의 **MST 총비용도 정확히 일치**했다. 실제 측정에서는 **희소 그래프일 때 인접 리스트 + Kruskal의 메모리 사용량과 실행시간이 더 작았고**, **밀집 그래프일 때 인접 행렬 + Prim의 메모리 사용량과 실행시간이 더 작았다.** 따라서 그래프의 밀도에 맞는 자료구조 선택과 MST 알고리즘 조합이 성능에 영향을 준다는 결론을 얻었다.
