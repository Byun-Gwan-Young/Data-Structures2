# 과제 05 - 순차 탐색과 이진 탐색 트리 탐색의 비교

## 1. 프로그램 개요

본 프로그램에서는 0부터 1000 사이의 서로 다른 정수 100개를 임의로 생성하고, 동일한 데이터를 정수 배열(Array)과 이진 탐색 트리(Binary Search Tree)에 저장하였다.

배열에는 생성된 순서 그대로 데이터를 저장하였으며 정렬하지 않았다.

이진 탐색 트리는 포인터를 이용한 연결 자료구조로 구현하였으며, 배열에 저장된 것과 동일한 데이터를 동일한 순서로 BST에 삽입하였다.

이후 0부터 1000 사이의 정수 50개를 추가로 생성하여 탐색 대상으로 사용하였다. 각각의 탐색 대상에 대해 배열에서는 순차 탐색을 수행하고, BST에서는 이진 탐색 트리 탐색을 수행하여 숫자 비교 횟수를 측정하였다.

---

## 2. 실험 결과

### 순차 탐색

- 총 비교 횟수: **4,735회**
- 평균 비교 횟수: **94.70회**

### 이진 탐색 트리 탐색

- 총 비교 횟수: **367회**
- 평균 비교 횟수: **7.34회**

### BST 생성 비용

100개의 데이터를 BST에 삽입하는 과정에서 발생한 총 비교 횟수는

**552회**

였다.

### BST 생성 비용을 포함한 전체 비용

BST 생성 비용과 50회의 BST 탐색 비용을 합하면

**552 + 367 = 919회**

이다.

실험 결과 총 50회의 탐색 중

- 탐색 성공: **5회**
- 탐색 실패: **45회**

가 발생하였다.

---

## 3. 순차 탐색과 BST 탐색의 성능 비교

이번 실험에서 순차 탐색은 총 4,735회의 비교가 발생하였고, 평균적으로 한 번의 탐색마다 94.70회의 비교가 발생하였다.

반면 BST 탐색은 총 367회의 비교가 발생하였으며, 평균 비교 횟수는 7.34회였다.

따라서 이번 실험에서는 BST 탐색이 순차 탐색보다 훨씬 적은 횟수의 비교를 수행하였다.

프로그램에서 계산한 결과 BST 탐색은 순차 탐색에 비해 약 **92.25%의 비교 횟수를 감소**시켰다.

이러한 차이가 발생한 가장 큰 이유는 순차 탐색의 경우 배열의 첫 번째 원소부터 하나씩 값을 비교해야 하기 때문이다.

특히 이번 실험에서는 50개의 탐색 대상 중 45개가 배열에 존재하지 않았다. 순차 탐색에서 찾고자 하는 값이 배열에 존재하지 않을 경우에는 100개의 원소를 전부 확인해야 하므로 한 번의 탐색에서 100회의 비교가 발생한다.

실제로 이번 실험에서도 대부분의 탐색 실패에 대해 순차 탐색 비교 횟수가 100회로 측정되었다.

반면 BST에서는 현재 노드의 값과 탐색 값을 비교한 후 탐색 값이 작으면 왼쪽, 크면 오른쪽 서브트리만 탐색한다. 따라서 탐색할 필요가 없는 많은 노드를 확인하지 않아도 되기 때문에 순차 탐색에 비해 비교 횟수가 크게 감소하였다.

---

## 4. BST 생성 비용을 고려한 성능 분석

BST는 탐색 과정에서는 효율적이지만 트리를 생성하는 과정에서 추가적인 비교가 필요하다.

배열의 경우 생성된 숫자를 배열에 순서대로 저장하기만 하면 되지만, BST에서는 새로운 데이터를 삽입할 때마다 루트에서 시작하여 기존 노드와 비교하면서 삽입할 위치를 찾아야 한다.

이번 실험에서는 BST를 생성하는 과정에서 총 **552회의 비교**가 발생하였다.

BST 탐색 과정에서 발생한 367회의 비교와 생성 과정의 비교 횟수를 합하면 전체 비용은 **919회**이다.

이를 순차 탐색의 전체 비교 횟수인 4,735회와 비교하면 BST 생성 비용까지 포함하더라도 BST를 이용한 방식의 비교 횟수가 훨씬 적었다.

또한 이번 실험 결과를 이용하여 BST 생성 비용을 회수하기 위해 필요한 탐색 횟수를 계산하면 약 **6.32회**로 나타났다.

즉, 이번에 생성된 데이터와 BST 구조를 기준으로 약 7회 이상 탐색을 수행할 경우 BST를 생성할 때 사용한 초기 비교 비용까지 고려하더라도 순차 탐색보다 효율적인 결과가 나타날 수 있음을 확인할 수 있다.

50회의 탐색을 수행한 이번 실험에서는 BST의 초기 생성 비용보다 반복적인 탐색에서 절약된 비교 횟수가 훨씬 컸다.

---

## 5. BST 구조에 따른 탐색 성능

BST의 탐색 성능은 트리의 구조에 따라 달라질 수 있다.

데이터가 적절한 순서로 삽입되어 BST가 비교적 균형 잡힌 형태가 되면 한 번의 비교를 수행할 때마다 탐색해야 하는 범위를 크게 줄일 수 있다.

이번 실험에서는 BST 탐색의 평균 비교 횟수가 7.34회로 나타났으며, 순차 탐색의 평균인 94.70회보다 매우 적은 결과가 나타났다.

하지만 BST가 항상 이러한 성능을 보장하는 것은 아니다.

예를 들어 다음과 같이 정렬된 값이 순서대로 입력된다고 가정할 수 있다.

10, 20, 30, 40, 50

이 경우 각각의 값이 이전 값의 오른쪽 자식으로 삽입되어 트리가 한쪽으로 치우친 형태가 된다.

이렇게 트리의 균형이 무너지면 원하는 값을 찾기 위해 여러 노드를 차례대로 확인해야 한다.

최악의 경우 BST가 연결 리스트와 비슷한 형태가 되어 데이터의 개수에 비례하는 비교가 필요할 수 있다.

따라서 BST의 탐색 성능은 단순히 데이터의 개수뿐만 아니라 데이터의 삽입 순서와 생성된 트리의 높이에도 영향을 받는다는 것을 알 수 있다.

---

## 6. 결론

이번 실험에서는 순차 탐색의 총 비교 횟수가 4,735회, 평균 비교 횟수가 94.70회였으며 BST 탐색에서는 총 367회, 평균 7.34회의 비교가 발생하였다.

BST를 생성하는 과정에서 552회의 비교가 추가로 발생하였지만 이를 포함하여도 전체 비교 횟수는 919회로, 순차 탐색의 4,735회보다 적었다.

특히 이번 탐색에서는 50개의 탐색 대상 중 45개가 데이터에 존재하지 않았기 때문에 순차 탐색에서 배열 전체를 확인하는 경우가 많이 발생하였다. 이로 인해 순차 탐색의 평균 비교 횟수가 크게 증가하였다.

반면 BST는 값의 크기를 이용하여 탐색할 방향을 결정하기 때문에 필요하지 않은 노드들을 탐색하지 않고 비교 횟수를 줄일 수 있었다.

따라서 이번 실험에서는 BST 생성에 필요한 초기 비용을 고려하더라도 반복적인 탐색에서는 BST가 순차 탐색보다 적은 비교 횟수를 보였다.

하지만 BST의 성능은 트리의 구조에 영향을 받기 때문에 입력 데이터의 순서에 따라 탐색 성능이 달라질 수 있다는 점도 함께 확인할 수 있었다.
