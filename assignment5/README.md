# 과제 05 - 순차 탐색과 이진 탐색 트리 탐색의 비교

## 1. 프로그램 개요

본 프로그램은 0부터 1000 사이의 서로 다른 정수 100개를 임의로 생성하고, 동일한 데이터를 정수 배열(Array)과 이진 탐색 트리(Binary Search Tree, BST)에 저장한 뒤 두 탐색 방법의 성능을 비교하기 위해 작성하였다.

배열에는 생성된 데이터를 발생 순서 그대로 저장하였으며 정렬하지 않았다.

이진 탐색 트리는 포인터를 이용한 연결 자료구조로 구현하였으며, 배열에 저장된 것과 동일한 100개의 정수를 동일한 발생 순서대로 BST에 삽입하였다.

이후 0부터 1000 사이의 정수 50개를 추가로 생성하여 탐색 대상으로 사용하고, 각 탐색 대상에 대하여 배열에서는 순차 탐색을, BST에서는 이진 탐색 트리 탐색을 수행하였다.

각 탐색 과정에서는 탐색 대상과 데이터 값을 비교한 횟수를 측정하였다.

또한 단순한 탐색 비교 횟수뿐만 아니라 BST 생성 과정에서 발생한 비교 비용과 실제 생성된 BST의 구조까지 함께 분석하였다.

# 4. 순차 탐색 결과 분석

순차 탐색에서는 총 **4,739회**의 비교가 발생하였으며 평균 비교 횟수는 **94.78회**였다.

순차 탐색은 배열의 첫 번째 원소부터 탐색 대상과 차례대로 비교하기 때문에 탐색 대상이 배열의 앞부분에 존재하는 경우에는 적은 비교만으로 탐색할 수 있다.

실제로 탐색 대상 `610`은 생성된 배열의 첫 번째 위치에 존재하였다.

따라서 다음과 같이 단 한 번의 비교만으로 탐색에 성공하였다.

```text
21   610   Found   1   Found   1
```

반면 탐색 대상이 배열에 존재하지 않는 경우에는 값이 존재하지 않는다는 사실을 확인하기 위해 배열의 100개 원소를 모두 확인해야 한다.

이번 실험에서는 총 50회의 탐색 중 **45회가 실패**하였다.

이 45번의 실패한 순차 탐색에서는 모두 **100회의 비교**가 발생하였다.

따라서 순차 탐색의 실패 시 평균 비교 횟수도 정확히 **100.00회**로 측정되었다.

탐색 성공 시에는 데이터가 저장된 위치에 따라 비교 횟수가 달라졌다.

예를 들어 `670`은 57번째 위치에서 발견되어 57회의 비교가 발생하였고, `139`는 41번째 위치에 존재하여 41회의 비교가 발생하였다.

따라서 순차 탐색은 탐색 성공 여부뿐만 아니라 **데이터가 배열의 어느 위치에 존재하는가**에 따라서도 성능이 크게 달라지는 것을 확인할 수 있었다.

# 5. BST 탐색 결과 분석

BST 탐색에서는 총 **393회**의 비교가 발생하였으며 평균 비교 횟수는 **7.86회**였다.

BST에서는 현재 노드의 값과 탐색 대상의 크기를 비교한 후 왼쪽 또는 오른쪽 서브트리 중 한 방향으로만 이동한다.

따라서 순차 탐색처럼 모든 데이터를 확인할 필요가 없다.

이번 실험에서 BST 탐색의 최소 비교 횟수는 **1회**, 최대 비교 횟수는 **15회**였다.

탐색 대상 `610`은 최초 생성된 값이므로 BST의 루트 노드에 위치한다.

따라서 한 번의 비교만으로 탐색에 성공하였다.

반대로 `492`를 탐색할 때에는 총 **15회의 비교**가 발생하였다.

```text
40   492   Not Found   100   Not Found   15
```

이번에 생성된 BST의 높이가 15였으므로, `492` 탐색은 BST의 비교적 깊은 위치까지 내려간 경우라고 볼 수 있다.

그럼에도 순차 탐색에서는 존재하지 않는 `492`를 확인하기 위해 100회의 비교가 필요했던 것과 비교하면 BST 탐색의 비교 횟수가 훨씬 적었다.

# 6. BST 생성 비용 분석

배열은 생성된 값을 발생 순서대로 저장하면 되기 때문에 별도의 위치 탐색 과정이 필요하지 않는다.

반면 BST에서는 새로운 값을 삽입할 때마다 루트 노드에서 시작하여 기존 노드와 값을 비교하면서 삽입할 위치를 찾아야 한다.

이번 실험에서는 BST 생성 과정에서 총

**651회**

의 비교가 발생하였다.

첫 번째 데이터는 비교 없이 루트가 되기 때문에 실제 비교를 통해 삽입되는 노드는 99개이다.

따라서 루트를 제외한 노드 하나를 삽입할 때 발생한 평균 비교 횟수는

**651 ÷ 99 ≒ 6.58회**

였다.

즉, BST는 탐색에서는 효율적이지만 트리를 만들기 위한 초기 비용이 발생한다는 것을 확인할 수 있다.

# 7. BST 구조 분석

이번 프로그램에서는 단순한 탐색 비교 결과뿐만 아니라 생성된 BST의 구조도 추가로 분석하였다.

결과는 다음과 같다.

- 전체 노드 수: **100개**
- BST 높이: **15**
- 리프 노드 수: **31개**
- 내부 노드 수: **69개**
- 평균 노드 깊이: **7.51**

BST의 탐색 성능은 트리 구조와 밀접한 관계가 있다.

이번 실험에서는 전체 노드가 100개였지만 트리의 높이는 15였다.

만약 100개의 노드가 모두 한쪽 방향으로 연결되는 최악의 BST가 생성되었다면 높이가 최대 100까지 증가할 수 있다.

이번 트리의 높이는 15였으므로 최악의 형태처럼 한쪽으로 완전히 치우친 구조는 아니었다.

또한 노드의 평균 깊이는 **7.51**이었고 실제 BST 탐색의 평균 비교 횟수는 **7.86회**였다.

두 값이 비슷한 범위로 측정된 것을 통해 실제 BST의 구조가 탐색 비교 횟수와 밀접하게 관련되어 있음을 확인할 수 있었다.

# 8. 순차 탐색과 BST 탐색의 성능 비교

두 탐색 방법에서 발생한 총 비교 횟수는 다음과 같다.

- 순차 탐색: **4,739회**
- BST 탐색: **393회**

BST 탐색에서는 순차 탐색에 비하여 총

**4,739 - 393 = 4,346회**

의 비교를 적게 수행하였다.

비율로 계산하면 약

**91.71%**

의 비교 횟수가 감소하였다.

이러한 큰 차이가 발생한 가장 중요한 이유 중 하나는 이번 실험에서 탐색 실패가 많이 발생했기 때문이다.

50번의 탐색 중 45번이 실패하였다.

순차 탐색은 탐색에 실패하면 100개의 데이터를 모두 확인해야 하지만, BST는 값의 크기를 기준으로 탐색할 방향을 결정하기 때문에 전체 노드를 확인할 필요가 없다.

실제로 탐색 실패 시 평균 비교 횟수는 다음과 같이 나타났다.

- 순차 탐색: **100.00회**
- BST 탐색: **8.02회**

즉, 이번 실험에서 존재하지 않는 값을 찾을 때 BST가 특히 큰 성능 차이를 보였다.

# 9. 탐색 성공과 실패에 따른 성능 차이

순차 탐색의 탐색 성공 시 평균 비교 횟수는 **47.80회**였다.

반면 탐색 실패 시에는 평균 **100.00회**의 비교가 발생하였다.

이는 순차 탐색의 경우 값이 존재하지 않으면 반드시 배열 전체를 검사해야 하기 때문이다.

BST에서는 탐색 성공 시 평균 **6.40회**, 탐색 실패 시 평균 **8.02회**의 비교가 발생하였다.

BST에서는 성공과 실패에 따른 평균 비교 횟수의 차이가 순차 탐색보다 훨씬 작았다.

따라서 이번 실험에서는 BST가 탐색 성공 여부와 관계없이 비교적 일정한 비교 횟수 안에서 탐색을 수행하는 모습을 보였다.

# 10. 최소 및 최대 비교 횟수 분석

순차 탐색의 비교 횟수 범위는 다음과 같다.

- 최소 비교 횟수: **1회**
- 최대 비교 횟수: **100회**

BST 탐색의 비교 횟수 범위는 다음과 같다.

- 최소 비교 횟수: **1회**
- 최대 비교 횟수: **15회**

순차 탐색에서는 탐색 대상의 위치와 탐색 성공 여부에 따라 비교 횟수가 1회부터 100회까지 크게 달라졌다.

반면 BST에서는 이번 실험에서 모든 탐색이 1회에서 15회 사이에 이루어졌다.

특히 BST에서 가장 많은 비교가 필요했던 경우에도 15회의 비교만 발생하였다.

이는 순차 탐색의 최대 비교 횟수인 100회의 약 15% 수준이다.

---

# 11. BST 생성 비용을 고려한 성능 비교

BST의 탐색 비교 횟수만 비교하면 순차 탐색보다 훨씬 적지만 BST에는 초기 생성 비용이 존재한다.

따라서 보다 공정한 비교를 위해 BST 생성 비용까지 포함하였다.

BST 생성 비용은

**651회**

이고, BST 탐색 비용은

**393회**

이다.

따라서 BST를 이용한 전체 비교 비용은

**651 + 393 = 1,044회**

이다.

순차 탐색에서 발생한 총 비교 횟수는

**4,739회**

이므로 BST 생성 비용을 포함하더라도

**4,739 - 1,044 = 3,695회**

의 비교가 적게 발생하였다.

비율로 계산하면 BST 생성 비용까지 포함한 경우에도 순차 탐색에 비해 약

**77.97%**

의 비교 횟수가 감소하였다.

따라서 이번 실험에서는 BST를 생성하는 데 필요한 초기 비용을 고려하더라도 전체적인 성능은 BST가 더 효율적인 결과를 보였다.

# 12. 손익분기점 분석

BST는 생성할 때 651회의 초기 비교 비용을 필요로 한다.

하지만 트리가 만들어진 이후에는 매번 탐색할 때 순차 탐색보다 적은 비교를 수행한다.

한 번의 탐색에서 두 방식의 평균 비교 횟수 차이는 다음과 같다.

**94.78 - 7.86 = 86.92회**

즉, BST를 사용하면 탐색 한 번당 평균 약 **86.92회**의 비교를 줄일 수 있었다.

BST 생성 비용인 651회를 탐색 한 번당 절약되는 비교 횟수로 나누면

**651 ÷ 86.92 ≒ 7.49**

가 된다.

따라서 이번 실험과 동일한 조건에서는 약 **8번의 탐색이 이루어지면 BST 생성에 사용한 초기 비교 비용을 상쇄할 수 있다.**

이번 프로그램에서는 총 50회의 탐색을 수행하였기 때문에 손익분기점인 약 8회를 크게 넘어섰다.

따라서 반복적인 탐색 환경에서는 BST를 생성하는 초기 비용보다 이후 탐색에서 절약되는 비교 횟수가 훨씬 크게 나타날 수 있음을 확인하였다.

# 13. BST 구조에 따른 성능 차이

BST의 탐색 성능은 항상 동일하지 않으며 데이터가 삽입되는 순서에 따라 생성되는 트리 구조에 영향을 받는다.

예를 들어 다음 값이 순서대로 삽입된다고 가정한다.

```text
10, 20, 30, 40, 50
```

이 경우 각 값이 이전 값보다 크기 때문에 새로운 값이 계속 오른쪽 자식으로 삽입된다.

결과적으로 다음과 같이 한쪽으로 치우친 BST가 생성된다.

```text
10
 \
  20
   \
    30
     \
      40
       \
        50
```

이러한 형태에서는 BST가 사실상 연결 리스트와 비슷하게 동작하게 된다.

노드가 100개인 경우 최악의 상황에서는 트리의 높이가 100까지 증가할 수 있으며, 하나의 값을 탐색하는 데 최대 100개의 노드를 비교해야 할 수 있다.

반대로 트리가 균형에 가까울수록 높이가 낮아지고 탐색해야 하는 노드 수도 감소한다.

이번 실험에서는 100개의 노드에 대해 BST 높이가 **15**였고 평균 탐색 비교 횟수는 **7.86회**였다.

따라서 이번에 생성된 BST는 극단적으로 한쪽으로 치우친 구조는 아니었으며, 이러한 구조가 순차 탐색보다 적은 비교 횟수를 보인 주요 원인 중 하나라고 볼 수 있다.

# 14. 결론

이번 실험에서는 동일한 100개의 정수를 배열과 이진 탐색 트리에 저장하고, 50개의 탐색 대상에 대해 순차 탐색과 BST 탐색을 수행하여 숫자 비교 횟수를 측정하였다.

순차 탐색에서는 총 **4,739회**, 평균 **94.78회**의 비교가 발생하였다.

반면 BST 탐색에서는 총 **393회**, 평균 **7.86회**의 비교가 발생하였다.

탐색 과정만 비교하면 BST 탐색은 순차 탐색보다 약 **91.71%의 비교 횟수를 감소**시켰다.

BST를 생성하는 과정에서는 추가로 **651회**의 비교가 발생하였다.

그러나 생성 비용과 탐색 비용을 모두 합한 **1,044회**도 순차 탐색의 **4,739회**보다 적었다.

BST 생성 비용을 포함하여 비교한 경우에도 약 **77.97%의 비교 횟수가 감소**하였다.

또한 손익분기점을 계산한 결과 이번 실험에서는 약 **8회의 탐색 이후부터 BST 생성 비용을 상쇄할 수 있는 것**으로 나타났다.

BST 구조를 추가로 분석한 결과 트리 높이는 **15**, 평균 노드 깊이는 **7.51**이었으며 실제 BST 탐색의 평균 비교 횟수는 **7.86회**였다.

이를 통해 BST의 구조와 실제 탐색 성능 사이에 밀접한 관계가 있음을 확인할 수 있었다.

순차 탐색은 구현이 간단하고 별도의 자료구조 생성 비용이 없다는 장점이 있지만 데이터의 수가 많아지거나 탐색 실패가 자주 발생하는 경우 많은 비교가 필요하다.

반면 BST는 초기 생성 비용이 발생하지만 한 번 트리를 생성한 후 동일한 데이터를 대상으로 여러 번 탐색할 경우 비교 횟수를 크게 줄일 수 있다.

따라서 이번 실험에서는 반복적인 탐색 환경에서 BST가 순차 탐색보다 효율적임을 확인할 수 있었다.

다만 BST의 실제 탐색 성능은 데이터의 삽입 순서에 따라 결정되는 트리의 높이와 균형 상태에 영향을 받으므로, BST의 성능을 평가할 때에는 단순한 데이터 개수뿐만 아니라 생성된 트리의 구조도 함께 고려해야 한다.
