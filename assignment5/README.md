# 과제 05 - 순차 탐색과 이진 탐색 트리 탐색의 비교

## 1. 프로그램 개요

본 프로그램은 0부터 1000 사이의 서로 다른 정수 100개를 임의로 생성하고, 동일한 데이터를 정수 배열(Array)과 이진 탐색 트리(Binary Search Tree, BST)에 저장한 뒤 두 탐색 방법의 성능을 비교하기 위해 작성하였다.

배열에는 생성된 데이터를 발생 순서 그대로 저장하였으며 정렬하지 않았다.

이진 탐색 트리는 포인터를 이용한 연결 자료구조로 구현하였으며, 배열에 저장된 것과 동일한 100개의 정수를 동일한 발생 순서대로 BST에 삽입하였다.

이후 0부터 1000 사이의 정수 50개를 추가로 생성하여 탐색 대상으로 사용하고, 각 탐색 대상에 대하여 배열에서는 순차 탐색을, BST에서는 이진 탐색 트리 탐색을 수행하였다.

각 탐색 과정에서는 탐색 대상과 데이터 값을 비교한 횟수를 측정하였다.

또한 단순한 탐색 비교 횟수뿐만 아니라 BST 생성 과정에서 발생한 비교 비용과 실제 생성된 BST의 구조까지 함께 분석하였다.

이번 실험에서 사용된 Random Seed는 다음과 같다.

**1790782980**

총 탐색 횟수는 50회이며 결과는 다음과 같다.

- 탐색 성공: **5회**
- 탐색 실패: **45회**
- 탐색 성공률: **10.00%**

---

### 2.2 순차 탐색 결과

순차 탐색에서는 다음과 같은 결과가 나타났다.

- 총 비교 횟수: **4,739회**
- 평균 비교 횟수: **94.78회**
- 최소 비교 횟수: **1회**
- 최대 비교 횟수: **100회**
- 탐색 성공 시 평균 비교 횟수: **47.80회**
- 탐색 실패 시 평균 비교 횟수: **100.00회**

순차 탐색은 배열의 첫 번째 원소부터 탐색 대상과 하나씩 비교하기 때문에 탐색 대상이 배열의 앞부분에 있으면 적은 횟수의 비교로 탐색할 수 있다.

실제로 탐색 대상 `610`은 배열의 첫 번째 위치에 저장되어 있었기 때문에 단 한 번의 비교만으로 탐색에 성공하였다.

반대로 찾으려는 값이 존재하지 않는 경우에는 배열의 100개 원소를 모두 확인해야 하므로 항상 100회의 비교가 발생하였다.

이번 실험에서는 탐색 실패가 45회였기 때문에 순차 탐색의 평균 비교 횟수가 매우 크게 나타났다.

## 3. BST 탐색 결과

BST 탐색에서는 다음과 같은 결과가 나타났다.

- 총 비교 횟수: **393회**
- 평균 비교 횟수: **7.86회**
- 최소 비교 횟수: **1회**
- 최대 비교 횟수: **15회**
- 탐색 성공 시 평균 비교 횟수: **6.40회**
- 탐색 실패 시 평균 비교 횟수: **8.02회**

BST에서는 현재 노드와 탐색 대상의 크기를 비교한 결과에 따라 왼쪽 또는 오른쪽 서브트리 중 하나만 탐색한다.

따라서 모든 데이터를 차례대로 확인하는 순차 탐색과 달리 탐색 대상과 관련이 없는 많은 노드를 확인하지 않아도 된다.

이번 실험에서 BST 탐색은 평균적으로 **7.86회**의 비교만 수행하였으며, 순차 탐색의 평균 비교 횟수인 **94.78회**와 큰 차이를 보였다.

특히 탐색 실패의 경우 순차 탐색은 항상 100회의 비교가 필요했지만 BST에서는 평균 **8.02회**의 비교만 발생하였다.

## 4. BST 생성 비용

BST는 배열과 달리 데이터를 단순히 저장하는 것으로 끝나지 않는다.

새로운 값을 삽입할 때마다 루트 노드부터 기존 노드의 값과 비교하면서 해당 값이 들어갈 위치를 찾아야 한다.

이번 실험에서 100개의 데이터를 BST에 삽입하는 과정에서 발생한 비교 횟수는 다음과 같다.

- BST 생성 총 비교 횟수: **651회**
- 루트를 제외한 노드 1개 삽입당 평균 비교 횟수: **6.58회**

첫 번째 데이터는 비교 없이 루트 노드가 되므로 나머지 99개의 데이터를 삽입하는 과정에서 비교가 발생하였다.

평균 삽입 비교 횟수는 다음과 같이 계산할 수 있다.

**651 ÷ 99 ≒ 6.58회**

---

## 5. BST 구조 분석

이번 실험에서 생성된 BST의 구조는 다음과 같다.

- 전체 노드 수: **100개**
- BST 높이: **15**
- 리프 노드 수: **31개**
- 내부 노드 수: **69개**
- 평균 노드 깊이: **7.51**

BST의 탐색 성능은 트리의 구조에 크게 영향을 받는다.

이번 실험에서 BST의 높이는 15였으며 전체 100개의 노드가 한쪽으로만 연결된 최악의 구조와 비교하면 비교적 낮은 높이를 유지하였다.

평균 노드 깊이는 7.51이었으며 실제 BST 탐색의 평균 비교 횟수도 7.86회로 유사한 수준으로 나타났다.

이는 대부분의 노드가 루트에서 너무 멀리 떨어져 있지 않았기 때문에 비교적 적은 횟수의 비교만으로 탐색이 가능했음을 보여준다.

다만 완전히 균형 잡힌 트리는 아니기 때문에 일부 탐색에서는 비교 횟수가 증가하였다.

예를 들어 탐색 대상 `492`는 BST 탐색에서 **15회**의 비교가 발생하였다.

이는 이번 BST의 높이인 15와 같으며, 상대적으로 깊은 위치까지 탐색이 진행된 경우라고 볼 수 있다.

## 6. 순차 탐색과 BST 탐색의 성능 비교

두 탐색 방법의 총 비교 횟수는 다음과 같다.

- 순차 탐색: **4,739회**
- BST 탐색: **393회**

BST 탐색은 순차 탐색보다 총

**4,739 - 393 = 4,346회**

의 비교를 적게 수행하였다.

비율로 계산하면 BST 탐색에서는 순차 탐색에 비해 약

**91.71%**

의 비교 횟수가 감소하였다.

이번 실험에서 이러한 큰 차이가 발생한 주요 원인은 탐색 실패 횟수가 많았기 때문이다.

50번의 탐색 중 45번이 실패하였는데, 순차 탐색에서는 값이 존재하지 않을 경우 배열 전체를 확인해야 하므로 매번 100회의 비교가 발생하였다.

반면 BST에서는 값이 존재하지 않더라도 현재 노드와 비교한 결과에 따라 탐색할 범위를 계속 줄여나갈 수 있으므로 평균 약 8회의 비교만으로 값이 존재하지 않는다는 사실을 확인할 수 있었다.

---

## 7. 탐색 성공과 실패에 따른 비교

### 순차 탐색

- 성공 시 평균 비교 횟수: **47.80회**
- 실패 시 평균 비교 횟수: **100.00회**

순차 탐색은 탐색 성공 여부뿐만 아니라 데이터가 배열의 어느 위치에 저장되어 있는지에 따라 성능 차이가 매우 크게 발생한다.

예를 들어 이번 실험에서 탐색 대상 `610`은 배열의 첫 번째 위치에 존재하므로 1회의 비교만으로 탐색할 수 있었다.

반면 배열에 존재하지 않는 값은 반드시 100개의 원소를 모두 검사해야 하므로 탐색 실패 시 항상 100회의 비교가 발생하였다.

### BST 탐색

- 성공 시 평균 비교 횟수: **6.40회**
- 실패 시 평균 비교 횟수: **8.02회**

BST에서는 탐색 성공과 실패 사이의 평균 비교 횟수 차이가 순차 탐색보다 훨씬 작게 나타났다.

이는 BST가 데이터의 크기 관계를 이용하여 탐색할 범위를 선택하기 때문이다.

이번 실험에서는 성공 여부와 관계없이 대부분의 탐색이 비교적 일정한 범위의 비교 횟수 안에서 수행되었다.

---

## 8. 최소 및 최대 비교 횟수 분석

순차 탐색의 비교 횟수 범위는 다음과 같다.

- 최소 비교 횟수: **1회**
- 최대 비교 횟수: **100회**

BST 탐색의 비교 횟수 범위는 다음과 같다.

- 최소 비교 횟수: **1회**
- 최대 비교 횟수: **15회**

순차 탐색에서는 탐색 대상의 위치 또는 탐색 성공 여부에 따라 비교 횟수가 1회에서 100회까지 매우 크게 달라졌다.

반면 BST에서는 최소 1회에서 최대 15회의 비교가 발생하였다.

이번 실험에서는 BST의 최악의 탐색에서도 순차 탐색의 최대 비교 횟수인 100회보다 훨씬 적은 15회의 비교만 발생하였다.

따라서 이번에 생성된 BST에서는 탐색 대상에 따른 비교 횟수의 변동도 순차 탐색보다 상대적으로 작게 나타났다.

---

## 9. BST 생성 비용을 포함한 성능 분석

BST는 탐색 과정에서는 비교 횟수가 매우 적지만 트리를 생성하기 위한 초기 비용이 필요하다.

이번 실험에서는 BST 생성 과정에서 **651회**의 비교가 발생하였다.

BST 탐색에서 발생한 393회의 비교와 합하면 전체 비교 비용은 다음과 같다.

**651 + 393 = 1,044회**

순차 탐색에서는 50회의 탐색에서 총 **4,739회**의 비교가 발생하였다.

따라서 BST 생성 비용을 포함하더라도

**4,739 - 1,044 = 3,695회**

의 비교를 적게 수행하였다.

비율로 계산하면 BST 생성 비용까지 모두 포함했을 때에도 순차 탐색에 비해 약

**77.97%**

의 비교 횟수가 감소하였다.

이를 통해 이번 실험에서는 BST의 초기 생성 비용을 고려하더라도 BST를 사용하는 것이 전체 비교 횟수 측면에서 더 효율적이었다는 것을 확인할 수 있었다.

---

## 10. 손익분기점 분석

BST는 생성 단계에서 651회의 초기 비교 비용이 필요하다.

하지만 한 번 생성한 이후에는 한 번의 탐색을 수행할 때 순차 탐색보다 평균적으로 훨씬 적은 비교를 수행한다.

한 번의 탐색에서 두 방법의 평균 비교 횟수 차이는 다음과 같다.

**94.78 - 7.86 = 86.92회**

즉, BST는 탐색 한 번당 평균 약 **86.92회**의 비교를 절약하였다.

따라서 BST 생성 비용 651회를 탐색당 절약되는 비교 횟수로 나누면 다음과 같다.

**651 ÷ 86.92 ≒ 7.49회**

이는 이번 실험과 같은 조건에서는 약 **8번 정도 탐색을 수행하면 BST를 생성하기 위해 사용한 초기 비용을 상쇄할 수 있다는 의미**이다.

이번 실험에서는 총 50회의 탐색을 수행하였으므로 손익분기점인 약 8회를 크게 넘어섰다.

따라서 반복적인 탐색이 이루어지는 상황에서는 BST의 초기 생성 비용보다 탐색 과정에서 얻는 이점이 더 크게 나타났다.

---

## 11. BST 구조에 따른 성능 차이

BST의 탐색 성능은 항상 일정한 것은 아니다.

BST의 구조는 데이터가 입력되는 순서에 따라 달라진다.

예를 들어 다음과 같이 오름차순으로 정렬된 값이 순서대로 삽입된다고 가정할 수 있다.

10, 20, 30, 40, 50

이 경우 새로운 값은 항상 현재 값보다 크기 때문에 계속 오른쪽 자식으로 삽입된다.

결과적으로 다음과 같이 한쪽으로 치우친 트리가 만들어질 수 있다.

```text
10
 \
  20
   \
    30
     \
      40
       \
        50
```

이처럼 BST가 한쪽으로 치우치면 트리의 높이가 커지고 탐색 과정에서 많은 노드를 방문해야 한다.

100개의 노드가 모두 한쪽 방향으로 연결되는 최악의 경우에는 트리 높이가 100이 될 수 있으며, 하나의 값을 탐색하기 위해 최대 100개의 노드를 비교해야 할 수도 있다.

이 경우 BST 탐색의 장점이 거의 사라지고 순차 탐색과 비슷한 수준의 성능이 나타날 수 있다.

반대로 BST가 균형에 가까운 구조를 가진다면 트리의 높이가 낮아지기 때문에 적은 비교 횟수로 탐색이 가능하다.

이번 실험에서는 100개의 노드에 대해 트리 높이가 15로 생성되었으며, BST 탐색의 평균 비교 횟수는 7.86회였다.

따라서 극단적으로 한쪽으로 치우친 BST가 생성된 것은 아니며, 이러한 구조가 순차 탐색에 비해 적은 비교 횟수를 보인 중요한 원인 중 하나라고 볼 수 있다.

## 12. 결론

이번 실험에서는 동일한 100개의 데이터를 배열과 이진 탐색 트리에 저장하고 50개의 탐색 대상에 대해 순차 탐색과 BST 탐색의 비교 횟수를 측정하였다.

순차 탐색에서는 총 **4,739회**, 평균 **94.78회**의 비교가 발생하였다.

반면 BST 탐색에서는 총 **393회**, 평균 **7.86회**의 비교가 발생하여 순차 탐색보다 약 **91.71% 적은 비교 횟수**를 보였다.

BST를 생성하는 과정에서는 추가로 **651회**의 비교 비용이 발생하였다.

그러나 생성 비용과 탐색 비용을 모두 합한 **1,044회** 역시 순차 탐색의 4,739회보다 크게 적었으며, 초기 생성 비용을 포함한 경우에도 약 **77.97%의 비교 횟수가 감소**하였다.

또한 이번 실험에서는 약 **8회의 탐색 이후 BST 생성 비용을 상쇄할 수 있는 것**으로 나타났다.

BST의 구조를 추가로 분석한 결과 트리 높이는 15, 평균 노드 깊이는 7.51이었다.

BST 탐색의 실제 평균 비교 횟수 역시 7.86회로 나타나 BST의 구조와 탐색 성능 사이에 밀접한 관계가 있음을 확인할 수 있었다.

순차 탐색은 별도의 자료구조 생성 비용이 없고 구현이 간단하다는 장점이 있지만, 데이터의 수가 많거나 탐색 실패가 자주 발생할 경우 많은 비교가 필요하다.

반면 BST는 초기 생성 비용이 필요하지만 한 번 생성한 이후 동일한 데이터에 대해 여러 번 탐색해야 하는 경우 비교 횟수를 크게 줄일 수 있다.

따라서 이번 실험에서는 반복적인 탐색 환경에서 BST가 순차 탐색보다 효율적이었으며, 동시에 BST의 실제 성능은 데이터의 삽입 순서와 트리의 높이 및 균형 상태에 따라 달라질 수 있다는 점을 확인하였다.
