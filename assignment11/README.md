# 과제 11: 삽입 정렬과 쉘 정렬의 성능 비교

## 1. 과제 목적

동일한 무작위 정수 데이터에 **삽입 정렬(Insertion Sort)**, **쉘 정렬 — 기본 간격(Shell's Original Sequence)**, **쉘 정렬 — Knuth 간격 수열(Knuth Sequence)**을 적용한다. 각 알고리즘에서 실제로 수행한 **데이터 값 사이의 비교 횟수**를 측정하고, 입력 크기와 간격 수열이 비교 횟수에 어떤 영향을 미치는지 분석한다.

## 2. 구현 환경 및 실험 방법

- **언어:** C (C11)
- **소스 코드:** `main.c`
- **컴파일 예시:** `gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c -o main`
- **실행:** macOS/Linux `./main` · Windows(GCC) `main.exe`
- **데이터 개수:** 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- **데이터 내용:** 0부터 1,000,000까지의 무작위 정수(중복 허용)
- **난수 생성:** `xorshift32`, 고정 시드 `20261101`. 매 실행 시 같은 데이터를 생성하여 실험을 재현할 수 있다. 난수 상태는 데이터 크기 순서대로 이어서 사용하며, 각각의 크기에서 원본 데이터는 한 번만 생성한다.
- **비교 조건:** 각 크기의 원본 배열을 세 번 복사한 다음 각 복사본에 서로 다른 정렬을 적용한다. 세 알고리즘은 **동일한 값과 동일한 초기 순서**를 입력받는다.
- **정렬 방향:** 오름차순
- **측정 지표:** 데이터 값 간 대소 비교 횟수(`uint64_t`)
- **측정 제외:** 난수 생성, 배열 복사, 인덱스/경계 조건 검사, 배열 이동 및 대입, `qsort` 기준 정렬, 결과 검증
- **검증 방식:** 각 결과의 오름차순 여부를 검사하고, C 표준 라이브러리의 `qsort`로 정렬한 기준 배열과 모든 원소가 일치하는지 확인한다. 검증 실패 시 오류를 출력하고 종료한다.

### 비교 횟수 집계 기준

삽입 정렬은 `data[j - 1] > key`, 쉘 정렬은 `data[j - gap] > key`를 실제로 평가할 때마다 비교 횟수를 **1 증가**시킨다. 비교 결과가 참이든 거짓이든 1회로 기록한다. 배열 시작에 도달하여 비교 자체가 수행되지 않은 경우에는 추가하지 않는다. 따라서 `j > 0`이나 `j >= gap` 같은 인덱스 검사는 비교 횟수에 포함되지 않는다.

### 사용한 간격 수열

1. **기본 간격:** `n / 2`부터 시작하여 정수 나눗셈으로 절반씩 감소시키고, 마지막에 `1`을 적용한다.
2. **Knuth 간격:** `h(1)=1`, `h(k+1)=3h(k)+1`로 생성한다. `n`보다 작은 최대 간격부터 역순으로 적용하여 `1`로 종료한다.

실제 사용된 간격 예시:

| 데이터 크기 | 기본 간격 | Knuth 간격 |
|---|---|---|
| 1,000 | 500, 250, 125, 62, 31, 15, 7, 3, 1 | 364, 121, 40, 13, 4, 1 |
| 20,000 | 10000, 5000, 2500, 1250, 625, 312, 156, 78, 39, 19, 9, 4, 2, 1 | 9841, 3280, 1093, 364, 121, 40, 13, 4, 1 |

## 4. 결과 분석 및 고찰

### 4.1 데이터 크기가 증가할 때 비교 횟수 변화

데이터가 많아질수록 세 알고리즘 모두 비교 횟수가 늘었지만, 증가 속도에는 큰 차이가 있었다. **삽입 정렬**은 1,000개일 때 254,622회였으나 2,000개일 때 966,104회로 약 **3.79배** 증가했다. 이후 2,000→4,000개는 약 **4.11배**, 4,000→8,000개는 약 **4.02배**, 8,000→16,000개는 약 **4.04배**였다. 데이터가 두 배가 될 때 비교 횟수가 약 네 배가 되는 모습으로, 무작위 입력에서 삽입 정렬의 평균적인 `O(n²)` 증가 경향과 부합한다.

반면 **기본 쉘 정렬**은 1,000개에서 15,512회, 16,000개에서 490,378회, 20,000개에서 632,035회였고, **Knuth 쉘 정렬**은 각각 13,456회, 439,197회, 520,394회였다. 입력 크기가 1,000개에서 20,000개로 **20배** 증가하는 동안 삽입 정렬의 비교 횟수는 약 **391.34배** 증가했으나, 기본 쉘 정렬은 약 **40.74배**, Knuth 쉘 정렬은 약 **38.67배** 증가했다. 이 실험에서는 쉘 정렬의 비교 횟수가 훨씬 완만하게 증가했다.

### 4.2 삽입 정렬과 쉘 정렬의 성능 차이

삽입 정렬은 현재 원소를 자기 앞의 정렬된 구간에 넣기 위해 **바로 앞 원소와 반복해서 비교**한다. 무작위 데이터에서는 작은 값이 뒤쪽에 있을 경우 해당 값을 앞쪽으로 옮기기 위한 비교가 많이 발생한다. 예를 들어 20,000개에서 삽입 정렬은 **99,644,465회**의 비교가 필요했다.

쉘 정렬은 처음부터 인접한 값만 비교하지 않고, **간격이 큰 원소들을 먼저 부분적으로 정렬**한다. 이렇게 멀리 떨어져 있던 원소들이 대략적인 위치로 이동하므로 마지막 간격 1의 삽입 정렬 과정에서는 큰 폭의 이동이 상대적으로 줄어든다. 실제로 20,000개에서 기본 쉘 정렬은 **632,035회**, Knuth 쉘 정렬은 **520,394회**만 비교했다. 따라서 동일한 실험에서 삽입 정렬 대비 각각 약 **157.66배**, **191.48배** 적은 비교를 수행했다.

### 4.3 쉘 정렬의 기본 간격과 Knuth 간격 수열 비교

이번 실험의 **6개 데이터 크기 모두 Knuth 수열의 비교 횟수가 더 적었다**.

| 데이터 크기 | 기본 간격 대비 Knuth의 비교 횟수 감소율 |
|---:|---:|
| 1,000 | 13.25% |
| 2,000 | 13.34% |
| 4,000 | 11.38% |
| 8,000 | 13.22% |
| 16,000 | 10.44% |
| 20,000 | 17.66% |

예를 들어 20,000개에서는 기본 간격이 **632,035회**, Knuth 수열이 **520,394회**로, Knuth가 **111,641회(17.66%)** 비교를 줄였다. 1,000개에서도 기본 간격 **15,512회**보다 Knuth **13,456회**가 **2,056회(13.25%)** 적었다. 이 데이터에서는 Knuth 간격이 처음부터 끝까지 비교 횟수 측면에서 유리했음을 확인할 수 있다.

### 4.4 간격 수열에 따라 차이가 발생하는 이유

쉘 정렬은 같은 삽입 정렬 방식을 사용하더라도 **어떤 간격으로, 몇 번, 어떤 순서로 원소들을 부분 정렬하는지**에 따라 이후 단계의 배열 상태가 달라진다.

기본 간격은 `n/2`를 계속 절반으로 줄여 적용한다. 20,000개에서는 `10000, 5000, 2500, ... , 2, 1`의 **14단계**가 수행된다. 반면 Knuth 수열은 `9841, 3280, 1093, ... , 4, 1`의 **9단계**이다. 두 방법은 간격의 크기와 변화 폭이 다르기 때문에 서로 다른 거리의 원소들을 비교·이동시키고, 최종 간격 1에 도달하기 전의 원소 배치도 달라진다.

이번 데이터에서 Knuth 수열은 기본 간격보다 단계 수가 적으면서도 전체 비교 횟수 역시 적었다. 이는 **간격을 많이 적용한다고 반드시 비교 횟수가 줄어드는 것은 아니며**, 적절한 간격을 선택하여 멀리 떨어진 원소들을 효율적으로 재배치하는 것이 중요함을 보여 준다. 다만 실제 절감량은 각 간격에서의 비교 횟수와 그 전 단계들이 만든 배열 상태가 함께 결정하므로, 단계 수 차이만으로 결과 전체를 설명할 수는 없다.

### 4.5 실험의 해석 범위

본 결과는 **고정된 난수 시드로 만든 무작위 데이터 한 세트씩** 측정한 값이며, 비교 횟수만을 측정했으므로 실제 실행 시간이나 모든 입력에서의 우수성을 뜻하지 않는다. 다른 난수 시드, 이미 정렬된 데이터, 역순 데이터에서는 비교 횟수와 두 간격 수열 사이의 우열이 달라질 수 있다. 그럼에도 본 실험 조건에서는 **Knuth 쉘 정렬 → 기본 쉘 정렬 → 일반 삽입 정렬 순으로 비교 횟수가 적었다**.
