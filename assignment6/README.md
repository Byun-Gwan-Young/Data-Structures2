# 과제 06 - 순차 탐색, BST, AVL 트리 성능 비교

## 1. 과제 개요

0부터 1000 사이의 정수를 100번 임의로 생성하여 다음 세 가지 자료구조에 동일한 순서로 저장하였다.

- 정수 배열(Array)
- 이진 탐색 트리(Binary Search Tree, BST)
- AVL 트리(AVL Tree)

새로운 값을 삽입하기 전에 각 자료구조에 동일한 값이 존재하는지 확인하고, 이미 존재하는 값은 삽입하지 않았다.

모든 삽입이 완료된 후 0부터 1000 사이의 정수 50개를 추가로 생성하여 동일한 탐색 대상에 대해 다음 방법으로 탐색을 수행하였다.

- 배열: Sequential Search
- BST: BST Search
- AVL: AVL Tree Search

각 자료구조의 생성 과정과 탐색 과정에서 발생한 숫자 비교 횟수를 측정하고, BST와 AVL 트리의 높이 차이에 따른 탐색 성능을 비교하였다.

## 5. 성능 비교 및 분석

### 5.1 배열 생성 비용

배열의 생성 과정에서는 총 **4,619회**의 비교가 발생하여 세 자료구조 중 가장 많은 비교가 발생하였다.

배열은 새로운 값이 생성될 때마다 배열의 첫 번째 원소부터 현재 저장된 마지막 원소까지 순차적으로 확인해야 한다.

특히 새로운 값이 기존 배열에 존재하지 않는 경우에는 현재 저장된 모든 값과 비교해야 하므로 저장된 데이터의 수가 증가할수록 비교 횟수가 증가한다.

따라서 이번 실험에서도 BST와 AVL 트리에 비해 매우 많은 비교가 발생하였다.

---

### 5.2 BST 생성 비용

BST의 생성 과정에서는 총 **559회**의 숫자 비교가 발생하였다.

BST에서는 현재 노드와 값을 비교한 후 찾으려는 값이 작으면 왼쪽, 크면 오른쪽으로 이동한다.

따라서 배열처럼 모든 데이터를 검사할 필요 없이 트리의 특정 경로만 따라가면 삽입 위치 또는 중복 여부를 확인할 수 있었다.

그 결과 배열의 4,619회보다 훨씬 적은 비교 횟수가 발생하였다.

---

### 5.3 AVL 트리 생성 비용

AVL 트리의 생성 과정에서는 총 **519회**의 숫자 비교가 발생하였다.

AVL 트리는 기본적으로 BST와 동일한 방법으로 삽입 위치를 탐색한다. 그러나 삽입이 완료된 후 트리의 균형이 깨지는 경우 LL, RR, LR, RL 회전을 수행하여 트리의 균형을 유지한다.

본 과제에서는 높이 계산, Balance Factor 검사, 회전 여부 판단은 숫자 비교 횟수에 포함하지 않고, 삽입하려는 값과 저장된 노드 값의 비교만 측정하였다.

이번 실험에서는 AVL 트리가 비교적 균형 잡힌 구조를 유지하면서 BST보다 적은 **519회**의 데이터 비교가 발생하였다.

## 6. BST와 AVL 트리의 높이 비교

이번 실험에서 BST의 높이는 **11**, AVL 트리의 높이는 **8**이었다.

두 자료구조에는 동일한 95개의 데이터가 동일한 순서로 삽입되었지만 트리 높이에 차이가 발생하였다.

일반 BST는 삽입되는 데이터의 순서에 따라 특정 방향으로 노드가 많이 배치될 수 있다. 따라서 트리가 불균형해질 수 있으며 높이가 증가할 수 있다.

반면 AVL 트리는 왼쪽 서브트리와 오른쪽 서브트리의 높이 차이를 확인하면서 필요할 경우 회전을 수행한다.

이 때문에 AVL 트리는 BST보다 전체적으로 균형 잡힌 구조를 유지하였고, 실제 실행 결과에서도 높이가 다음과 같이 나타났다.

```text
BST height : 11
AVL height : 8
```

따라서 이번 실험에서는 AVL 트리가 BST보다 **3단계 낮은 높이**를 유지하였다.

---

## 7. 트리 높이가 탐색 성능에 미치는 영향

BST와 AVL 트리의 탐색 방법은 기본적으로 동일하다.

루트 노드부터 시작하여 탐색 대상과 현재 노드의 값을 비교하고, 값이 작으면 왼쪽, 크면 오른쪽으로 이동한다.

따라서 탐색 과정에서 수행하는 비교 횟수는 루트에서 해당 값 또는 탐색이 종료되는 위치까지의 경로 길이와 관련이 있다.

이번 실험 결과는 다음과 같다.

```text
BST height : 11
AVL height : 8

BST average search comparisons : 7.32
AVL average search comparisons : 6.60
```

AVL 트리는 BST보다 높이가 낮았으며, 평균 탐색 비교 횟수 역시 더 적게 측정되었다.

BST의 평균 비교 횟수는 **7.32회**, AVL 트리는 **6.60회**로 AVL 트리가 탐색 시 평균적으로 더 적은 노드를 방문하였다.

이를 통해 트리의 높이가 낮고 균형이 잘 유지될수록 탐색 과정에서 방문해야 하는 노드의 수 역시 줄어들 수 있다는 것을 확인할 수 있었다.

## 8. 순차 탐색과 트리 탐색 비교

50개의 탐색 대상에 대한 결과는 다음과 같다.

```text
Sequential Search : 4588회 / 평균 91.76회
BST Search        : 366회  / 평균 7.32회
AVL Search        : 330회  / 평균 6.60회
```

순차 탐색은 평균 **91.76회**의 비교가 발생하여 BST와 AVL 트리에 비해 비교 횟수가 매우 많았다.

이번 실험에서는 50개의 탐색 대상 중 실제로 저장된 값과 일치한 값이 다음 4개였다.

```text
349
520
813
669
```

나머지 대부분의 검색은 실패하였다.

배열에서 탐색에 실패하는 경우 저장된 **95개의 데이터를 모두 비교**해야 한다.

따라서 탐색 실패가 많이 발생한 이번 실험에서는 순차 탐색의 평균 비교 횟수가 매우 크게 나타났다.

반면 BST와 AVL 트리는 값의 크기를 기준으로 탐색할 방향을 결정하기 때문에 전체 데이터를 확인하지 않고 탐색을 종료할 수 있었다.

## 9. 생성 비용과 탐색 비용 종합 비교

### 생성 비교 횟수

```text
Array : 4619
BST   : 559
AVL   : 519
```

### 탐색 평균 비교 횟수

```text
Sequential Search : 91.76
BST Search        : 7.32
AVL Search        : 6.60
```

배열은 구현 구조가 단순하지만 새로운 데이터를 삽입할 때 중복 검사를 위해 기존 데이터를 순차적으로 확인해야 하기 때문에 생성 비용이 가장 크게 나타났다.

또한 탐색에서도 원하는 값이 존재하지 않으면 배열 전체를 검사해야 하므로 탐색 비용 역시 가장 높았다.

BST는 값의 대소 관계를 이용하여 특정 경로만 탐색하기 때문에 배열보다 생성과 탐색 모두 훨씬 적은 숫자 비교가 발생하였다.

AVL 트리는 BST와 동일한 탐색 구조를 사용하면서도 회전을 통해 트리의 균형을 유지한다. 그 결과 이번 실험에서는 BST보다 낮은 높이를 유지하였으며 평균 탐색 비교 횟수도 가장 적게 나타났다.

단, AVL 트리는 실제 프로그램 수행 시간 측면에서는 삽입 후 높이 갱신과 Balance Factor 확인, 회전 등의 추가 연산이 필요하다. 이번 과제의 숫자 비교 횟수에서는 이러한 연산을 제외하였기 때문에 생성 비교 횟수는 AVL 트리가 가장 적게 측정되었다.

## 10. 결론

이번 실험을 통해 배열, BST, AVL 트리의 생성 및 탐색 성능 차이를 확인할 수 있었다.

배열은 생성 과정에서 **4,619회**, 탐색 과정에서 총 **4,588회**의 비교가 발생하여 가장 많은 숫자 비교를 수행하였다.

BST는 생성 과정에서 **559회**, 탐색 과정에서 총 **366회**의 비교가 발생하여 배열에 비해 훨씬 효율적인 결과를 보였다.

AVL 트리는 생성 과정에서 **519회**, 탐색 과정에서 총 **330회**의 비교가 발생하였다.

또한 BST의 높이가 11인 것에 비해 AVL 트리의 높이는 8로 더 낮게 유지되었다.

실제 평균 탐색 비교 횟수 역시 BST는 **7.32회**, AVL 트리는 **6.60회**로 AVL 트리가 더 적었다.

따라서 이번 실험에서는 **트리의 균형과 높이가 실제 탐색 성능에 직접적인 영향을 미친다는 것을 확인할 수 있었다.**

특히 AVL 트리는 회전을 통해 균형을 유지함으로써 일반 BST보다 낮은 높이를 유지하였고, 그 결과 보다 안정적인 탐색 성능을 보였다.
