# 과제 02 — 이진트리 프로그램 구현

## 1. 파일 구성

| 파일 | 기능 |
|---|---|
| `array_bintree.c` | 1번: 배열 입력·눕힌 출력·통계·완전/포화/편향 판별 |
| `linked_bintree.c` | 2번: 연결 구조 입력·눕힌 출력·통계·완전/포화/편향 판별 |
| `compare.c` | 3번: 실제 메모리 할당량 비교 및 두 구현의 자식·부모·형제 조회 |
| `bintree.c` | 위 필수 기능을 한 프로그램으로 제공하는 원본 기반 합본 수정본 |
| `예제실행결과.txt` | 수정한 비교 프로그램에서 실제 출력한 메모리 실험 결과 |

각 C 파일은 독립적으로 컴파일된다. 세 파일로 제출한다면 `array_bintree.c`, `linked_bintree.c`, `compare.c`와 이 설명서를 사용한다. `bintree.c`는 같은 기능의 합본이며 별도로 실행한다. 소스들을 한꺼번에 링크하지 않는다.


## 2. 입력과 메뉴

| 괄호 표기 | 의미 |
|---|---|
| `A` | 자식이 없는 루트 |
| `A(B,C)` | 왼쪽 B, 오른쪽 C |
| `A(B)` 또는 `A(B,)` | 왼쪽 자식만 존재 |
| `A(,C)` | 오른쪽 자식만 존재 |
| `A()` 또는 `A(,)` | 루트만 존재 |
| `Root(Left,Right)` | 여러 글자 이름도 사용 가능 |

이름은 ASCII 영문/숫자/밑줄 1~15자이며 대소문자를 구분한다. **중복 이름은 거부**한다. 같은 이름으로 두 구현이 서로 다른 노드를 검색하는 모호함을 없애기 위한 정책이다. 입력은 한 줄 최대 511바이트이며 공백은 허용한다. 길이 초과 시 남은 줄을 모두 버린 뒤 같은 입력을 다시 받는다. 빈 트리는 입력 오류로 처리한다.

잘못된 괄호, 세 번째 자식, 불필요한 뒷부분, 너무 긴 이름은 오류이다. 새 트리 생성에 실패하면 이전의 정상 트리를 유지한다.

- 배열 프로그램: 1 입력, 2 출력, 3 정보, 4 형태 판별, 5 내부 배열, 0 종료.
- 연결 프로그램: 1 입력, 2 출력, 3 정보, 4 형태 판별, 0 종료.
- 비교 프로그램: 1 입력, 2 현재 메모리, 3 형태별 메모리 실험, 4 관계 조회, 0 종료.
- 합본: 1 입력, 배열 기능 2 to 5, 연결 기능 6 to 8, 현재 메모리 9, 형태별 실험 10, 관계 조회 11, 0 종료.

배열과 합본/비교 프로그램은 높이 20까지만 받는다. 연결 단독 프로그램은 배열 인덱스 제한을 적용하지 않는다. 다만 동일한 입력 길이 제한은 적용된다.

## 3. 구현 및 정의

배열은 `Cell { char label[16]; }`과 동적 배열을 사용한다. 루트 인덱스는 1, 왼쪽 `2i`, 오른쪽 `2i+1`, 부모 `i/2`이다. 이름의 첫 바이트가 널 문자이면 빈 칸이다. 연결 노드는 이름과 좌우 자식 포인터를 갖고 노드마다 할당된다. 두 파서는 같은 문자열에서 각각 독립적으로 자신의 표현을 구성한다.

출력은 오른쪽 → 자신 → 왼쪽 순서이며, 깊이당 6칸을 들여쓴다. 한쪽 자식이 없는 경우 `-`로 빈 위치를 표시한다.

통계는 전체 노드 수, 단말 수, 비단말 수(전체−단말), 높이, 차수를 제공한다. **높이는 루트 레벨을 1로 계산한다.** 차수는 모든 노드 중 자식 수의 최댓값이다.

- 완전: 마지막 레벨 이전이 가득 차며 마지막 레벨이 왼쪽부터 채워져 있다. 배열은 인덱스 1..n의 연속성을, 연결은 큐의 레벨 순회를 검사한다. 큐 할당 실패는 '아니오'가 아니라 '판별 실패'로 출력한다.
- 포화: 모든 레벨이 가득 차 있다. 배열은 완전성과 `n=2^h−1`을 검사한다. 높이 20 제한으로 시프트 범위가 안전하다. 연결은 양쪽 서브트리의 포화 여부와 같은 높이를 재귀적으로 검사하므로 깊은 트리에서도 위험한 시프트를 사용하지 않는다.
- 편향: 모든 노드의 차수가 1 이하인 하나의 경로이다. 좌편향·우편향·지그재그를 구분하고 단일 노드도 편향으로 처리한다.

높이의 간선 수 정의나 편향을 한쪽 방향만으로 제한하는 정의를 쓰는 수업이라면 이 프로그램의 명시된 정의와 맞추어야 한다.

## 4. 메모리 실험과 분석 — 과제 3-[1]

비교 프로그램 메뉴 3 / 합본 메뉴 10은 일반·완전·편향 트리를 **실제로 생성하여 배열과 연결 구조에 적재**한다. 각 그룹의 노드 수는 10개와 15개로 동일하다. 할당된 배열 칸 수와 연결 노드 수에 실행 환경의 `sizeof`를 곱한다.

- 배열 요청량: `capacity × sizeof(Cell)`.
- 연결 요청량: `n × sizeof(TreeNode)`.
- 배열의 0번 칸과 빈 슬롯은 포함하고 구조체 내부 패딩도 `sizeof`에 포함한다.
- 관리 변수, 이름 중복 검사표 등 파서 작업 공간, 임시 큐, 재귀 스택, 메모리 할당기의 부가 비용은 제외한다. 운영체제의 RSS나 프로그램 전체 메모리 측정이 아니다.

**`capacity=2^h`는 이 구현의 전체 레벨 예약 정책이다.** 모든 배열 기반 트리에 필요한 최소 크기라는 뜻은 아니다. 가장 큰 사용 인덱스 M에 대해 M+1칸만 예약하는 다른 구현도 가능하다. 메모리 비교 결론은 이 정책에 따른다.

검증 환경은 `sizeof(Cell)=16`, `sizeof(TreeNode)=32`인 64비트 macOS이다.

| 형태 | n | h | 배열 칸 수 | 배열 요청량(B) | 연결 요청량(B) | 배열/연결 |
|---|---:|---:|---:|---:|---:|---:|
| 일반 | 10 | 5 | 32 | 512 | 320 | 1.60 |
| 완전 | 10 | 4 | 16 | 256 | 320 | 0.80 |
| 편향 | 10 | 10 | 1024 | 16384 | 320 | 51.20 |
| 일반 | 15 | 6 | 64 | 1024 | 480 | 2.13 |
| 완전(포화) | 15 | 4 | 16 | 256 | 480 | 0.53 |
| 편향 | 15 | 15 | 32768 | 524288 | 480 | 1092.27 |

일반 10개 예제는 `A(B(D,E(,H)),C(,F(G(I,J),)))`이다. 완전 예제는 인덱스 1..n을 채우고, 편향 예제는 N1부터 Nn까지 왼쪽으로 연결한다. 사용한 입력 문자열도 실험 표 아래에 출력한다.

완전 트리는 빈칸이 적고 포인터를 저장하지 않아 이 환경에서 배열이 유리하거나 같다. 위 일반 예제들은 성격 상 연결이 유리하지만, 모든 일반 트리에서 연결이 유리한 것은 아니다. 편향 트리는 h=n이므로 이 배열 정책에서 공간이 `16×2^n`으로 늘어나는 반면 연결은 `32n`으로 늘어난다.

일반적인 손익 조건은 `2^h × sizeof(Cell) < n × sizeof(TreeNode)`이다. 50% 사용률은 위의 16/32바이트 환경에서만 얻어지는 기준이며, 다른 환경은 프로그램이 계산한 크기로 판단한다.

## 5. 관계 조회와 효율성 — 과제 3-[2]

사용자가 노드 이름을 입력하면 양쪽 구현에서 왼쪽 자식·오른쪽 자식·부모·형제를 출력한다. 루트의 부모/형제는 없으며, 찾지 못한 이름도 안내한다.

배열은 이름을 앞에서부터 검색하고 위치 i로 관계를 계산한다. 연결은 전위 탐색하면서 현재 노드의 부모를 함께 전달하여 **찾는 순간 부모도 반환**한다. 부모 포인터 필드를 추가하거나 루트에서 재탐색하지 않는다. 형제는 부모의 반대쪽 자식이다.

| 작업 | 배열 | 연결 |
|---|---|---|
| 이름 검색 | 최악 O(capacity)=O(2^h) | 최악 O(n) |
| 검색 완료 후 네 관계 확인 | 각각 O(1) | 부모도 확보했으므로 각각 O(1) |
| 관계 조회 보조 공간 | O(1) | 재귀 스택 O(h) |
| 부모 정보 없이 위치만 주어진 경우 부모 찾기 | O(1) | 별도 탐색 O(n) 필요 |

노드 검색은 배열의 확인한 칸 수와 연결의 방문한 노드 수를 각각 센다. 검색 성공 후 네 관계를 각 1단계로 간주한다. **이것은 비교를 위한 논리적 단계 모형이며 CPU 명령 수나 실제 경과 시간이 아니다.** 재귀 호출, 문자열 비교 등의 비용을 모두 동등하게 측정하는 지표도 아니다.

`A(B(D,E),C(,F))`에서 F는 배열 인덱스 7이므로 7+4=11단계, 연결 전위 탐색에서는 여섯 번째이므로 6+4=10단계이다. 이전의 부모 재탐색 방식에서 나온 14단계 등의 수치를 수정본에 적용하면 안 된다.

관계 확인은 수정본에서 양쪽 모두 O(1)이므로, 이름 검색 순서와 빈 슬롯 수가 총 단계 수에 영향을 준다. 조밀한 트리는 배열의 공간 낭비가 적고, 성긴 트리는 배열 검색이 빈칸까지 방문한다. 어떤 모양에서도 무조건 한쪽이 빠르다고 일반화할 수 없다.

## 6. 검증

네 C 파일을 각각 `-std=c11 -Wall -Wextra -Wpedantic -Werror`로 macOS에서 컴파일했다. 다음 자동 검증을 통과했다.

- 일반/완전/포화/좌편향/우편향/지그재그/단일 노드 7개 기본 사례.
- 무작위 트리 40개에서 독립 기준 계산과 양쪽 구현의 통계·형태 결과 비교.
- 중복 이름, 16자 이름, 괄호 오류, 세 번째 자식, 잘못된 문자 거부.
- 15자 이름 허용, 너무 긴 줄을 소비한 후 정상 입력 복구, 잘못된 메뉴 처리.
- 실패한 트리 입력 이후 기존 트리 보존, 입력 도중 EOF 종료.
- 좌우 편향 높이 20 허용 및 21 거부; 연결 단독 높이 32 판별.
- 루트/내부/단말/없는 노드 관계 조회 및 실제 메모리 표.

Windows 실행 및 메모리 오류 검사 도구를 통한 검증은 수행하지 않았다.
