# 과제 07 — 인접 행렬과 인접 리스트의 성능 비교

## 1. 과제 목표

정점이 100개인 **무방향 단순 그래프**를 인접 행렬과 인접 리스트로 각각 표현하고, **메모리 사용량**과 **간선 삽입·삭제 / 연결 여부 확인 / 인접 정점 출력의 비교 횟수**를 측정한다. 그래프 밀도에 따라 어느 표현 방법이 효율적인지 실험 결과를 분석한다.

- 정점 번호: `0` ~ `99`
- 자기 간선 및 중복 간선: **없음**
- 희소 그래프: 정점 100개, 간선 100개 (가능한 4,950개 중 약 **2.02%**)
- 밀집 그래프: 정점 100개, 간선 4,000개 (가능한 4,950개 중 약 **80.81%**)
- 같은 그래프에서는 **행렬과 리스트에 동일한 간선**을 저장한다.

## 2. 구현 방법

### 그래프 생성

가능한 `(u, v)` (`u < v`) 4,950개를 생성하여 무작위로 섞은 다음, 앞에서부터 100개 또는 4,000개의 간선을 선택한다. 따라서 자기 간선과 중복 간선이 발생하지 않는다. **선택한 간선 집합 하나를 두 표현 방식에 동시에 적용**한다.

재현 가능한 실험을 위해 기본 난수 시드 `20261015`를 사용한다. 동일한 시드라면 Windows와 macOS에서도 동일한 그래프가 생성되도록 `xorshift32` 방식의 난수를 사용했다. 실행 시 다른 시드를 지정하면 다른 그래프로도 시험할 수 있다.

### 그래프 표현

- **인접 행렬**: `int adj[100][100]`. 무방향 간선 `(u, v)`를 `adj[u][v] = adj[v][u] = 1`로 저장한다.
- **인접 리스트**: `Node *head[100]`과 단일 연결 리스트. 무방향 간선 하나를 양쪽 리스트에 **노드 2개**로 저장한다. 노드는 맨 앞에 삽입한다.

그래프를 만든 **이후에**, 행렬과 리스트에 **동일한** 삽입·삭제·연결 확인·인접 정점 확인을 수행한다.

### 비교 횟수 계산 기준

| 연산 | 인접 행렬 | 인접 리스트 |
|---|---|---|
| 간선 삽입 | `adj[u][v]` 존재 여부 확인 **1회** | 중복 여부를 찾기 위해 `u`의 리스트에서 확인한 노드 수. 중복이 없으면 머리에 바로 추가하므로 다른 노드의 비교는 없음 |
| 간선 삭제 | `adj[u][v]` 존재 여부 확인 **1회** | `(u → v)`와 `(v → u)` 노드를 제거하기 위해 **양쪽 리스트에서 확인한 노드 수 합계** |
| 연결 여부 | `adj[u][v]` 확인 **1회** | `u`의 리스트에서 `v`를 찾거나 리스트 끝에 도달할 때까지 확인한 노드 수 |
| 인접 정점 출력 | `adj[u][0]` ~ `adj[u][99]` 확인 **100회** | `u`의 리스트 전체를 확인한 노드 수 (= 차수) |

여기서 비교 횟수는 그래프의 원소 또는 간선 정보를 **직접 확인한 횟수**이다. 반복문 조건 검사, 포인터 대입, 결과 표시용 임시 배열 정렬, 별도의 정합성 검증 등은 포함하지 않는다.

**테스트 수행 순서:** 처음 그래프에 존재하지 않는 간선 1개를 추가하고, **처음 그래프에 존재했던 다른 간선** 1개를 삭제한다. 이렇게 하면 각 그래프의 최종 간선 수는 원래대로 100개 또는 4,000개가 유지된다. 이후 동일한 정점 쌍에 대해 연결 여부를 확인하고, 동일한 정점의 인접 정점을 출력한다.

## 3. 실행 방법

필요 환경: C11을 지원하는 GCC 컴파일러. 별도 라이브러리 불필요.

**macOS / Linux (터미널)**

```bash
gcc -std=c11 -Wall -Wextra main.c -o assignment07
./assignment07
```

**Windows (PowerShell, GCC 설치 환경)**

```powershell
gcc -std=c11 -Wall -Wextra main.c -o assignment07.exe
.\assignment07.exe
```

다른 그래프로 시험할 때는 실행 명령 뒤에 **양의 정수 시드**를 붙인다. 예: `./assignment07 12345` 또는 `.\assignment07.exe 12345`.

`sample_output.txt`는 **기본 시드로 직접 컴파일·실행한 전체 출력 결과**다.

### 메모리 계산

`sizeof`로 산정했다. 그래프를 저장하기 위한 자료구조 자체와 관리 정보는 포함하고, **난수/간선 생성용 임시 배열, 결과 표시용 배열, 실행 코드 영역은 제외**했다.

- 행렬 구조체: 정점 수 및 간선 수 `int` 2개 + `int[100][100]` = `8 + 40,000 = 40,008 Bytes`.
- 리스트 구조체: 정점 수 및 간선 수 `int` 2개 + 헤드 포인터 100개 = `8 + 800 = 808 Bytes`.
- 리스트 간선 노드: `sizeof(Node) = 16 Bytes` (정점 번호 `int`, 다음 노드 포인터, 정렬 패딩 포함, 64비트 환경).
- 희소 리스트: `808 + (2 × 100 × 16) = 4,008 Bytes`.
- 밀집 리스트: `808 + (2 × 4,000 × 16) = 128,808 Bytes`.

`sizeof(Node)`와 포인터 크기는 컴파일 환경에 따라 달라질 수 있어 **메모리 수치는 플랫폼에 따라 달라질 수 있다**. `malloc` 구현 자체의 힙 관리 메타데이터는 자료구조 크기에 포함하지 않았다.

## 5. 결과 분석

### 5-1. 희소 그래프: 인접 리스트가 공간 및 인접 정점 순회에 유리

희소 그래프에는 간선이 100개뿐이다. 무방향이므로 평균 차수는 `2 × 100 / 100 = 2`에 불과하다.

- **메모리:** 행렬은 연결이 없는 칸까지 모두 저장하므로 **40,008 Bytes**를 사용했다. 리스트는 실제 간선 노드 200개만 저장하여 **4,008 Bytes**로, 행렬에 비해 약 **90% 절약**했다.
- **간선 삽입·삭제:** 행렬은 각각 1회 확인했지만, 리스트는 삽입에 5회, 삭제에 4회가 필요했다. 리스트는 간선이 존재하는지 찾거나 두 방향의 노드를 제거하기 위해 리스트를 순회해야 하기 때문이다.
- **연결 여부:** 행렬은 직접 접근하여 1회, 리스트는 3회 확인했다. 희소 그래프는 리스트가 짧아 차이가 크지는 않았다.
- **인접 정점 출력:** 행렬은 항상 100칸을 확인하여 100회, 리스트는 선택된 정점에 실제로 연결된 **3개 노드만** 확인하여 3회였다.

따라서 **간선이 적고 인접 정점들을 나열하는 작업이 많은 희소 그래프**에는 메모리 절감과 순회 효율 측면에서 인접 리스트가 적합하다. 단, 특정 두 정점 간 연결 여부를 자주 확인해야 한다면 행렬의 직접 접근이 장점이다.

### 5-2. 밀집 그래프: 인접 행렬이 공간 및 간선 조회에 유리

밀집 그래프에는 간선이 4,000개이고 평균 차수는 `2 × 4,000 / 100 = 80`이다. 각 정점에 연결된 이웃이 상당히 많아 리스트가 길어진다.

- **메모리:** 행렬은 희소 그래프와 동일하게 **40,008 Bytes**를 사용했다. 리스트는 간선 노드를 8,000개 저장하면서 **128,808 Bytes**를 사용해, 오히려 행렬보다 약 **3.22배** 커졌다.
- **간선 삽입·삭제:** 행렬은 각각 1회였지만, 리스트는 삽입 78회·삭제 84회였다. 리스트가 길어져서 삽입 전 중복 확인과 삭제할 노드 탐색에 더 많은 비교가 필요했다.
- **연결 여부:** 행렬 1회, 리스트 57회였다. 밀집 그래프에서는 직접 접근이 가능한 행렬의 장점이 두드러졌다.
- **인접 정점 출력:** 행렬은 100회, 리스트는 81회였다. 리스트가 여전히 조금 덜 확인하지만, 대부분의 정점이 서로 연결되어 있어 **희소 그래프만큼의 차이는 없었다**.

따라서 **간선이 많거나 연결 여부 확인·간선 수정이 빈번한 밀집 그래프**에는 인접 행렬이 유리하다.

### 5-3. 최종 결론

| 선택 기준 | 상대적으로 적합한 방식 | 이유 |
|---|---|---|
| 간선이 적고 메모리를 절약해야 할 때 | **인접 리스트** | 실제 존재하는 간선만 노드로 저장 |
| 특정 정점의 이웃을 빠르게 모두 탐색할 때 (희소 그래프) | **인접 리스트** | 해당 정점의 차수만큼만 확인 |
| 간선이 매우 많을 때 | **인접 행렬** | 밀집 그래프에서는 고정 크기의 배열이 포인터 기반 리스트보다 공간 효율적일 수 있음 |
| 두 정점의 직접 연결 여부를 반복 확인할 때 | **인접 행렬** | `matrix[u][v]` 한 번 확인 |
| 간선의 존재 확인·삽입·삭제가 빈번할 때 | **인접 행렬** | 조회할 원소 수가 보통 1개 (이번 구현 기준) |

**실험 결론:** 같은 100개 정점이라도 간선이 100개에서 4,000개로 늘면서 리스트 메모리는 크게 증가했고, 리스트에서 필요한 탐색 횟수도 늘었다. 반면 행렬 메모리(40,008 Bytes)와 직접 연결 여부 확인(1회)은 변하지 않았다. 따라서 **희소 그래프에서는 인접 리스트**, **밀집 그래프에서는 인접 행렬**을 우선 고려하는 것이 적절하다. 다만 리스트의 실제 비교 횟수는 선택한 정점·간선과 노드 순서에 따라 달라지며, 이번 측정은 **한 개의 시드로 수행한 실험 사례**다.
